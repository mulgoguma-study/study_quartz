# K3s MSA 실습 빠른 시작 가이드

## 단계별 실습 순서

### Step 1: 프로젝트 구조 생성 (5분)

```bash
# 프로젝트 디렉토리 생성
mkdir -p msa-k3s-lab/{gateway,user-service,product-service,k8s}
cd msa-k3s-lab

# 각 서비스에 파일 생성
# gateway/
touch gateway/{main.go,go.mod,Dockerfile}

# user-service/
touch user-service/{main.go,go.mod,Dockerfile}

# product-service/
touch product-service/{main.go,go.mod,Dockerfile}

# k8s manifests
touch k8s/manifests.yaml
```

앞서 제공한 코드를 각 파일에 복사합니다.

### Step 2: K3s 클러스터 구축 (10분)

**마스터 노드 (개발 서버):**

```bash
# K3s 설치
curl -sfL https://get.k3s.io | sh -

# 설치 확인
sudo systemctl status k3s
kubectl get nodes

# 워커 연결을 위한 정보 저장
MASTER_IP=$(hostname -I | awk '{print $1}')
NODE_TOKEN=$(sudo cat /var/lib/rancher/k3s/server/node-token)

echo "Master IP: $MASTER_IP"
echo "Node Token: $NODE_TOKEN"
```

**워커 노드:**

```bash
# 마스터에서 출력된 정보 사용
export MASTER_IP="<마스터_IP>"
export NODE_TOKEN="<노드_토큰>"

# 워커로 조인
curl -sfL https://get.k3s.io | K3S_URL=https://${MASTER_IP}:6443 \
  K3S_TOKEN=${NODE_TOKEN} sh -
```

**마스터에서 확인:**

```bash
kubectl get nodes
# NAME     STATUS   ROLES                  AGE   VERSION
# master   Ready    control-plane,master   5m    v1.28.x
# worker   Ready    <none>                 1m    v1.28.x
```

### Step 3: 로컬 레지스트리 구성 (5분)

```bash
# Podman으로 레지스트리 실행
podman run -d \
  --name registry \
  -p 5000:5000 \
  --restart=always \
  docker.io/library/registry:2

# 레지스트리 동작 확인
curl http://localhost:5000/v2/_catalog

# K3s에 insecure 레지스트리 설정
sudo mkdir -p /etc/rancher/k3s
sudo tee /etc/rancher/k3s/registries.yaml > /dev/null <<EOF
mirrors:
  "localhost:5000":
    endpoint:
      - "http://${MASTER_IP}:5000"
configs:
  "localhost:5000":
    tls:
      insecure_skip_verify: true
EOF

# K3s 재시작
sudo systemctl restart k3s

# 워커 노드에서도 동일하게 설정 후 재시작
# sudo systemctl restart k3s-agent
```

### Step 4: 이미지 빌드 및 푸시 (10분)

```bash
cd msa-k3s-lab

# Gateway 빌드
cd gateway
podman build -t localhost:5000/gateway:v1.0 .
podman push localhost:5000/gateway:v1.0

# User Service 빌드
cd ../user-service
podman build -t localhost:5000/user-service:v1.0 .
podman push localhost:5000/user-service:v1.0

# Product Service 빌드
cd ../product-service
podman build -t localhost:5000/product-service:v1.0 .
podman push localhost:5000/product-service:v1.0

cd ..

# 이미지 확인
curl http://localhost:5000/v2/_catalog
```

**자동화 스크립트 생성:**

```bash
cat > build-all.sh <<'EOF'
#!/bin/bash
set -e

REGISTRY="${REGISTRY:-localhost:5000}"
VERSION="${VERSION:-v1.0}"

services=("gateway" "user-service" "product-service")

for service in "${services[@]}"; do
    echo "Building $service..."
    cd $service
    podman build -t ${REGISTRY}/${service}:${VERSION} .
    podman push ${REGISTRY}/${service}:${VERSION}
    cd ..
    echo "✓ $service completed"
done

echo "All services built and pushed successfully!"
EOF

chmod +x build-all.sh
./build-all.sh
```

### Step 5: 애플리케이션 배포 (5분)

```bash
# Manifest 파일의 이미지 태그 수정 (v1.0으로)
sed -i 's|:latest|:v1.0|g' k8s/manifests.yaml

# 배포
kubectl apply -f k8s/manifests.yaml

# 배포 상태 확인 (Pod가 Running이 될 때까지 대기)
watch kubectl get pods -o wide
```

### Step 6: 서비스 테스트 (5분)

```bash
# 마스터 IP 확인
MASTER_IP=$(hostname -I | awk '{print $1}')

# Gateway 서비스 테스트
curl http://${MASTER_IP}:30080/
curl http://${MASTER_IP}:30080/users
curl http://${MASTER_IP}:30080/products

# 로드밸런싱 확인 (hostname이 변경되는지 확인)
echo "=== Testing Load Balancing ==="
for i in {1..10}; do
    echo "Request $i:"
    curl -s http://${MASTER_IP}:30080/users | jq -r '.hostname'
done
```

### Step 7: Scale Out 테스트 (10분)

**수동 스케일링:**

```bash
# 현재 Pod 수 확인
kubectl get pods -l app=gateway

# 5개로 증가
kubectl scale deployment gateway --replicas=5

# 스케일링 확인
kubectl get pods -l app=gateway -o wide

# 다시 2개로 감소
kubectl scale deployment gateway --replicas=2
```

**HPA 테스트:**

```bash
# HPA 상태 확인
kubectl get hpa

# 부하 생성 (새 터미널)
while true; do 
    curl -s http://${MASTER_IP}:30080/users > /dev/null
    curl -s http://${MASTER_IP}:30080/products > /dev/null
done

# HPA 모니터링 (원래 터미널)
watch kubectl get hpa

# Pod 증가 확인
watch 'kubectl get pods -l app=gateway -o wide'

# 부하 중단 후 스케일 다운 확인 (5-10분 소요)
```

### Step 8: 고급 테스트

**Pod 배포 위치 확인:**

```bash
# 어느 노드에 Pod가 배포되었는지 확인
kubectl get pods -o wide | grep -E 'NAME|gateway|user|product'

# 특정 노드에만 배포하기 (NodeSelector)
kubectl label nodes worker environment=production

# Deployment에 nodeSelector 추가
kubectl edit deployment gateway
# spec.template.spec에 추가:
#   nodeSelector:
#     environment: production
```

**롤링 업데이트 테스트:**

```bash
# 코드 수정 (예: gateway/main.go의 version을 2.0.0으로 변경)

# 재빌드
cd gateway
podman build -t localhost:5000/gateway:v2.0 .
podman push localhost:5000/gateway:v2.0
cd ..

# 이미지 업데이트
kubectl set image deployment/gateway gateway=localhost:5000/gateway:v2.0

# 롤링 업데이트 상태 확인
kubectl rollout status deployment/gateway

# 롤백 (문제가 있을 경우)
kubectl rollout undo deployment/gateway
```

**서비스 장애 시뮬레이션:**

```bash
# User Service Pod 하나 삭제
kubectl delete pod -l app=user-service --force --grace-period=0 | head -n 1

# 자동 복구 확인
watch kubectl get pods -l app=user-service

# 서비스 가용성 확인 (삭제 중에도 서비스 가능해야 함)
while true; do
    curl -s http://${MASTER_IP}:30080/users | jq '.service'
    sleep 1
done
```

## 트러블슈팅 체크리스트

### Pod가 ImagePullBackOff 상태일 때

```bash
# 레지스트리 연결 확인
curl http://localhost:5000/v2/_catalog

# 이미지가 레지스트리에 있는지 확인
curl http://localhost:5000/v2/gateway/tags/list

# Pod 상세 로그 확인
kubectl describe pod <pod-name>

# registries.yaml 확인
cat /etc/rancher/k3s/registries.yaml
sudo systemctl restart k3s
```

### Pod가 CrashLoopBackOff 상태일 때

```bash
# 로그 확인
kubectl logs <pod-name>

# 이전 컨테이너 로그 확인
kubectl logs <pod-name> --previous

# 컨테이너 내부 확인 (가능한 경우)
kubectl exec -it <pod-name> -- sh
```

### HPA가 작동하지 않을 때

```bash
# Metrics Server 확인
kubectl get deployment metrics-server -n kube-system

# 메트릭 확인
kubectl top nodes
kubectl top pods

# HPA 상세 정보
kubectl describe hpa gateway-hpa
```
