## 답변
### 1. K3s 네트워크 구조

네, 맞습니다! K3s는 기본적으로 **Flannel CNI**를 사용하여 클러스터 내 모든 노드(마스터/워커)의 Pod들이 같은 네트워크에서 통신할 수 있습니다.

- Pod 간 직접 통신 가능 (Pod IP 사용)
- Service를 통한 로드밸런싱 및 서비스 디스커버리
- 클러스터 DNS를 통한 서비스 이름으로 통신 (`service-name.namespace.svc.cluster.local`)

##### 📋 제공된 내용 요약

###### 1. **네트워크 구조** ✅

- K3s는 Flannel CNI로 모든 노드의 Pod가 같은 네트워크에서 통신
- Service를 통한 로드밸런싱 및 DNS 기반 서비스 디스커버리

###### 2. **MSA Go 코드** ✅

- **Gateway**: API Gateway (포트 8080)
- **User Service**: 사용자 관리 서비스 (포트 8081)
- **Product Service**: 상품 관리 서비스 (포트 8082)
- 각 서비스는 hostname과 request count를 반환하여 로드밸런싱 확인 가능

###### 3. **경량 컨테이너 이미지** ✅

- Gateway: **scratch** 기반 (최소 크기)
- User/Product Service: **alpine** 기반 (디버깅 편의성)
- Multi-stage 빌드로 최적화

###### 4. **Scale Out & CI/CD** ✅

- **HPA (Horizontal Pod Autoscaler)**: CPU 50% 기준 자동 스케일
- **ArgoCD**: GitOps 기반 CD
- **Forgejo**: Git 서버 (Gitea fork)
- GitHub Actions 스타일 워크플로우

###### 5. **Scale Out 테스트** ✅

- 수동 스케일링: `kubectl scale`
- 자동 스케일링: HPA + 부하 생성 스크립트
- 부하 테스트 스크립트와 실시간 모니터링

```bash
make status            # 전체 상태 확인
```
