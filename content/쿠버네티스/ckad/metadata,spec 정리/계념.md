## Kubernetes 리소스의 4가지 최상위 필드

모든 K8s 리소스는 이 구조를 가져요.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata: ...   # "이 오브젝트가 누구인가"
spec: ...        # "이 오브젝트가 무엇을 해야 하는가"
status: ...      # "이 오브젝트가 지금 어떤 상태인가" (K8s가 채움, 직접 작성 X)
```

---

## metadata — "신분증"

**K8s 시스템이 오브젝트를 식별하고 관리하기 위한 정보**예요. 내용 자체와는 무관해요.

> 쉽게 말하면: "이 리소스가 _어디에 있고_, _뭐라고 불리고_, _어떤 그룹에 속하는지_"

```yaml
metadata:
  name: my-app          # K8s API가 오브젝트를 찾는 고유 키
  namespace: production # 논리적 분리 공간
  labels:               # 셀렉터로 쿼리/그룹핑하는 태그
  annotations:          # 시스템/도구용 부가 정보 (쿼리 불가)
  uid:                  # K8s가 자동 부여하는 진짜 고유 ID
  resourceVersion:      # 변경 감지용 버전 (낙관적 락)
  creationTimestamp:    # 생성 시각
```

metadata는 **K8s 컨트롤 플레인이 소비**해요. etcd에 저장되고, API 서버가 오브젝트를 찾고, 셀렉터가 Pod을 매칭하고, 가비지 컬렉터가 ownerReference를 추적하는 것 — 모두 metadata 기반이에요.

---

## spec — "설계도 / 계약서"

**사용자가 원하는 상태(desired state)를 선언**하는 곳이에요.

> 쉽게 말하면: "이 리소스가 _무엇을 실행하고_, _어떻게 동작해야 하는지_"

```yaml
spec:
  replicas: 3           # 원하는 파드 수
  containers:           # 어떤 컨테이너를 실행할지
    - image: nginx:1.25
  resources:            # 얼마나 자원을 쓸지
  ...
```

spec은 **K8s 컨트롤러가 소비**해요. Deployment Controller는 spec.replicas를 읽어서 "현재 2개인데 3개가 되어야 하네" 하고 Pod을 하나 더 만들어요. 이게 K8s의 **Reconciliation Loop** (조정 루프)예요.

---

## 둘의 관계 — Desired State vs Current State

```
사용자가 spec을 작성
        ↓
  K8s API Server 저장 (etcd)
        ↓
  Controller가 spec을 읽음
        ↓
  status(현재 상태)와 비교
        ↓
  차이가 있으면 → 실제 동작으로 맞춤
        ↓
  status를 업데이트
```

- **spec** = 내가 원하는 것 (선언)
- **status** = 실제로 된 것 (관찰)
- **K8s의 역할** = spec과 status의 간극을 줄이는 것

## Go 관점으로 보면

K8s 리소스는 Go struct로 정의되어 있어요. `client-go` 기준으로 보면 구조가 명확해져요.

```go
// Deployment 타입 정의 (k8s.io/api/apps/v1)
type Deployment struct {
    metav1.TypeMeta   `json:",inline"`  // apiVersion, kind
    metav1.ObjectMeta `json:"metadata"` // metadata 전체
    Spec   DeploymentSpec   `json:"spec"`
    Status DeploymentStatus `json:"status"`
}

// ObjectMeta — metadata 필드들
type ObjectMeta struct {
    Name            string
    Namespace       string
    Labels          map[string]string
    Annotations     map[string]string
    UID             types.UID
    ResourceVersion string
    // ...
}

// DeploymentSpec — spec 필드들
type DeploymentSpec struct {
    Replicas *int32
    Selector *metav1.LabelSelector
    Template v1.PodTemplateSpec
    Strategy DeploymentStrategy
    // ...
}
```

즉, **metadata는 모든 리소스가 공유하는 공통 struct** (`ObjectMeta`)이고, **spec은 리소스마다 다른 struct**예요. 그래서 metadata 규칙은 리소스 종류에 상관없이 동일하고, spec은 리소스마다 완전히 달라요.

---

한 줄 요약:

- **metadata** → K8s가 오브젝트를 _관리_하기 위한 정보
- **spec** → 사용자가 _원하는 상태_를 선언하는 곳
