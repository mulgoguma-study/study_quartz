CKAD 시험 범위 기준으로 상세하게 정리할게요.정리한 내용 요약하면:

**Metadata 섹션**

- `name` / `namespace` 규칙 (DNS 1123, 길이 제한, 허용 문자)
- `labels` — key prefix/name 구조, 표준 `app.kubernetes.io/*` 레이블
- `annotations` — labels와 차이점, 용도
- `ownerReferences` — Cascade Delete 동작 원리

**Spec 섹션**

- 전체 리소스별 `apiVersion` + `kind` 한 눈에 정리
- Pod spec 핵심 필드 전체 (container, probe 3가지 방식, volume 타입 5가지)
- Deployment `selector` ↔ `template.labels` 일치 규칙
- Service 타입별 spec
- Job/CronJob 타임아웃/재시도 관련 필드
- ConfigMap/Secret (type 목록 포함)
- nodeSelector / affinity / tolerations 스케줄링 3종
- Pod/Container 레벨 securityContext
- ResourceQuota / LimitRange
- 메타데이터 관련 `kubectl` 빠른 명령 모음

시험 중에 `--dry-run=client -o yaml` 패턴이 제일 자주 쓰이니 마지막 섹션도 참고하세요!



# CKAD — Metadata & Spec 완전 정리

## 1. 기본 구조 (모든 리소스 공통)

```yaml
apiVersion: <group>/<version>   # 또는 core group이면 그냥 <version>
kind: <Kind>
metadata:
  ...
spec:
  ...
```

---

## 2. Metadata

### 2-1. 필수 필드

|필드|설명|
|---|---|
|`name`|리소스 이름. 네임스페이스 내 유일|
|`namespace`|소속 네임스페이스. 생략 시 `default`|

### 2-2. name 규칙 (RFC 1123 / DNS Subdomain)

- 소문자 알파벳, 숫자, `-`, `.` 만 허용
- 반드시 알파벳 또는 숫자로 시작하고 끝나야 함
- 최대 **253자** (대부분의 리소스), Pod name은 최대 **63자**
- `_`, 대문자, 특수문자 사용 불가

```
# 올바른 예
my-app
web-server-v2
backend.prod

# 잘못된 예
My_App        # 대문자, 언더스코어
-my-app       # 하이픈으로 시작
my app        # 공백
```

### 2-3. namespace 규칙

- `name`과 동일한 DNS Label 규칙 적용
- 최대 **63자**
- 기본 네임스페이스: `default`, `kube-system`, `kube-public`, `kube-node-lease`

### 2-4. labels

```yaml
metadata:
  labels:
    app: my-app
    env: production
    version: "1.0"
    tier: backend
    app.kubernetes.io/name: my-app
    app.kubernetes.io/version: "1.0"
    app.kubernetes.io/component: backend
    app.kubernetes.io/part-of: my-system
    app.kubernetes.io/managed-by: helm
```

**규칙**

- key: `prefix/name` 형식 (prefix 선택사항)
    - prefix: DNS subdomain, 최대 **253자**, `/`로 구분
    - name: 최대 **63자**, 알파벳·숫자·`-`·`_`·`.` 허용, 알파벳·숫자로 시작/끝
- value: 최대 **63자**, 빈 문자열 허용, 알파벳·숫자로 시작/끝
- `kubernetes.io/`, `k8s.io/` prefix는 시스템 예약

**권장 표준 레이블 (app.kubernetes.io)**

```yaml
app.kubernetes.io/name        # 앱 이름 (예: mysql)
app.kubernetes.io/instance    # 인스턴스 구분 (예: mysql-prod)
app.kubernetes.io/version     # 앱 버전 (예: 5.7.21)
app.kubernetes.io/component   # 컴포넌트 역할 (예: database)
app.kubernetes.io/part-of     # 상위 앱 이름 (예: wordpress)
app.kubernetes.io/managed-by  # 관리 도구 (예: helm)
```

### 2-5. annotations

```yaml
metadata:
  annotations:
    description: "메인 백엔드 서버"
    contact: "team@example.com"
    kubectl.kubernetes.io/last-applied-configuration: ...
```

**labels와의 차이점**

- 셀렉터로 사용 불가
- 값에 제한 없음 (길이 제한 없음, 구조화된 데이터도 가능)
- 주로 도구/시스템 메타데이터, 자유 형식 메모 용도

### 2-6. ownerReferences

직접 작성하는 경우는 드물지만 CKAD에서 이해 필요.

```yaml
metadata:
  ownerReferences:
    - apiVersion: apps/v1
      kind: ReplicaSet
      name: my-replicaset
      uid: <uid>
      controller: true
      blockOwnerDeletion: true
```

Deployment → ReplicaSet → Pod 순으로 자동 설정됨. 상위 리소스 삭제 시 종속 리소스도 함께 삭제 (Cascade Delete).

## 4. Pod spec 핵심 필드

### 4-1. 전체 구조

```yaml
spec:
  # 컨테이너
  initContainers: [...]
  containers: [...]           # 필수

  # 스케줄링
  nodeSelector: {}
  nodeName: ""
  affinity: {}
  tolerations: []

  # 네트워크
  hostNetwork: false
  dnsPolicy: ClusterFirst
  dnsConfig: {}

  # 볼륨
  volumes: []

  # 서비스어카운트
  serviceAccountName: default
  automountServiceAccountToken: true

  # 종료
  restartPolicy: Always       # Always | OnFailure | Never
  terminationGracePeriodSeconds: 30

  # 보안
  securityContext: {}

  # 기타
  imagePullSecrets: []
  priorityClassName: ""
```

### 4-2. container 상세

```yaml
containers:
  - name: app                         # 필수, 파드 내 유일
    image: nginx:1.25                 # 필수
    imagePullPolicy: IfNotPresent     # Always | IfNotPresent | Never

    # 명령어
    command: ["/bin/sh"]              # ENTRYPOINT 오버라이드
    args: ["-c", "echo hello"]        # CMD 오버라이드

    # 포트 (정보 제공용, 실제 차단/허용과 무관)
    ports:
      - name: http
        containerPort: 8080
        protocol: TCP

    # 환경변수
    env:
      - name: ENV_VAR
        value: "literal value"
      - name: SECRET_VAR
        valueFrom:
          secretKeyRef:
            name: my-secret
            key: password
      - name: CONFIG_VAR
        valueFrom:
          configMapKeyRef:
            name: my-config
            key: setting
      - name: POD_NAME
        valueFrom:
          fieldRef:
            fieldPath: metadata.name    # Downward API
    envFrom:
      - configMapRef:
          name: my-config
      - secretRef:
          name: my-secret

    # 리소스
    resources:
      requests:
        cpu: "100m"
        memory: "128Mi"
      limits:
        cpu: "500m"
        memory: "256Mi"

    # 볼륨 마운트
    volumeMounts:
      - name: config-vol
        mountPath: /etc/config
        readOnly: true
      - name: data-vol
        mountPath: /data
        subPath: myapp        # 볼륨 내 특정 경로만 마운트

    # 프로브
    livenessProbe:
      httpGet:
        path: /healthz
        port: 8080
      initialDelaySeconds: 10
      periodSeconds: 5
      failureThreshold: 3

    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 3

    startupProbe:
      httpGet:
        path: /healthz
        port: 8080
      failureThreshold: 30
      periodSeconds: 10

    # 보안 컨텍스트
    securityContext:
      runAsUser: 1000
      runAsNonRoot: true
      readOnlyRootFilesystem: true
      allowPrivilegeEscalation: false
      capabilities:
        add: ["NET_ADMIN"]
        drop: ["ALL"]

    # 라이프사이클 훅
    lifecycle:
      postStart:
        exec:
          command: ["/bin/sh", "-c", "echo started"]
      preStop:
        exec:
          command: ["/bin/sh", "-c", "sleep 5"]

    # 종료 관련
    terminationMessagePath: /dev/termination-log
    terminationMessagePolicy: File
```

### 4-3. Probe 방식 3가지

```yaml
# HTTP GET
httpGet:
  path: /healthz
  port: 8080
  httpHeaders:
    - name: Custom-Header
      value: value

# TCP Socket
tcpSocket:
  port: 3306

# Exec
exec:
  command: ["cat", "/tmp/healthy"]
```

### 4-4. 볼륨 타입

```yaml
volumes:
  # ConfigMap → 파일로 마운트
  - name: config-vol
    configMap:
      name: my-config
      items:
        - key: app.conf
          path: app.conf

  # Secret → 파일로 마운트
  - name: secret-vol
    secret:
      secretName: my-secret

  # emptyDir: 파드 수명과 동일
  - name: tmp-vol
    emptyDir: {}

  # hostPath: 노드 파일시스템
  - name: host-vol
    hostPath:
      path: /data
      type: DirectoryOrCreate

  # PVC
  - name: pvc-vol
    persistentVolumeClaim:
      claimName: my-pvc

  # projected: 여러 소스를 하나의 볼륨으로
  - name: projected-vol
    projected:
      sources:
        - configMap:
            name: my-config
        - secret:
            name: my-secret
```

## 5. Deployment spec

```yaml
spec:
  replicas: 3
  selector:                         # 필수, 변경 불가
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate             # RollingUpdate | Recreate
    rollingUpdate:
      maxUnavailable: 1             # 정수 또는 % (기본 25%)
      maxSurge: 1                   # 정수 또는 % (기본 25%)
  minReadySeconds: 0
  revisionHistoryLimit: 10
  paused: false
  template:                         # Pod 템플릿
    metadata:
      labels:
        app: my-app                 # selector.matchLabels와 반드시 일치
    spec:
      ...                           # Pod spec과 동일
```

> **selector와 template.labels 일치 규칙** `selector.matchLabels`의 모든 키-값이 `template.metadata.labels`에 포함되어야 함.

## 6. Service spec

```yaml
spec:
  type: ClusterIP                   # ClusterIP | NodePort | LoadBalancer | ExternalName
  selector:
    app: my-app                     # 이 레이블을 가진 Pod으로 트래픽 전달
  ports:
    - name: http
      protocol: TCP
      port: 80                      # 서비스 포트
      targetPort: 8080              # 파드 컨테이너 포트 (또는 포트 이름)
      nodePort: 30080               # NodePort 타입일 때 (30000-32767)
  clusterIP: ""                     # 생략 시 자동 할당, None이면 Headless
  sessionAffinity: None             # None | ClientIP
```

## 7. Job / CronJob spec

```yaml
# Job
spec:
  completions: 1                    # 성공해야 할 총 횟수
  parallelism: 1                    # 동시 실행 파드 수
  backoffLimit: 6                   # 실패 재시도 한도
  activeDeadlineSeconds: 100        # Job 전체 타임아웃
  ttlSecondsAfterFinished: 60       # 완료 후 자동 삭제
  template:
    spec:
      restartPolicy: OnFailure      # Job은 Never 또는 OnFailure만 허용
      containers: [...]

# CronJob
spec:
  schedule: "*/5 * * * *"           # cron 표현식
  concurrencyPolicy: Allow          # Allow | Forbid | Replace
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  startingDeadlineSeconds: 60
  suspend: false
  jobTemplate:
    spec:
      ...                           # Job spec과 동일
```

## 8. ConfigMap / Secret

```yaml
# ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-config
data:
  key1: value1
  app.conf: |
    setting1=true
    setting2=false
binaryData:
  icon.png: <base64>

# Secret
apiVersion: v1
kind: Secret
metadata:
  name: my-secret
type: Opaque                        # Opaque | kubernetes.io/tls | kubernetes.io/dockerconfigjson 등
data:
  password: <base64 encoded>
stringData:                         # 평문으로 작성 가능 (우선순위 높음)
  password: mysecretpassword
```

**Secret type 목록**

|type|용도|
|---|---|
|`Opaque`|범용 (기본값)|
|`kubernetes.io/tls`|TLS 인증서|
|`kubernetes.io/dockerconfigjson`|레지스트리 인증|
|`kubernetes.io/service-account-token`|SA 토큰|
|`kubernetes.io/ssh-auth`|SSH 키|

## 9. 스케줄링 관련

### nodeSelector (단순)

```yaml
spec:
  nodeSelector:
    disktype: ssd
    kubernetes.io/os: linux
```

### affinity (고급)

```yaml
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:  # 필수
        nodeSelectorTerms:
          - matchExpressions:
              - key: disktype
                operator: In                # In | NotIn | Exists | DoesNotExist | Gt | Lt
                values: ["ssd"]
      preferredDuringSchedulingIgnoredDuringExecution: # 선호
        - weight: 1
          preference:
            matchExpressions:
              - key: zone
                operator: In
                values: ["us-east-1a"]

    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: frontend
          topologyKey: kubernetes.io/hostname   # 같은 노드에 배치

    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: my-app
            topologyKey: kubernetes.io/hostname  # 다른 노드로 분산
```

### tolerations (Taint 허용)

```yaml
spec:
  tolerations:
    - key: "special"
      operator: Equal               # Equal | Exists
      value: "gpu"
      effect: NoSchedule            # NoSchedule | PreferNoSchedule | NoExecute
    - key: "node.kubernetes.io/not-ready"
      operator: Exists
      effect: NoExecute
      tolerationSeconds: 300
```

## 11. ResourceQuota / LimitRange

```yaml
# ResourceQuota: 네임스페이스 전체 제한
apiVersion: v1
kind: ResourceQuota
metadata:
  name: ns-quota
  namespace: dev
spec:
  hard:
    pods: "10"
    requests.cpu: "4"
    requests.memory: 4Gi
    limits.cpu: "8"
    limits.memory: 8Gi
    configmaps: "10"
    secrets: "10"
    services: "5"
    persistentvolumeclaims: "4"

# LimitRange: 파드/컨테이너 기본값 및 범위 설정
apiVersion: v1
kind: LimitRange
metadata:
  name: lr
  namespace: dev
spec:
  limits:
    - type: Container
      default:          # limits 기본값
        cpu: "500m"
        memory: 256Mi
      defaultRequest:   # requests 기본값
        cpu: "100m"
        memory: 128Mi
      max:
        cpu: "2"
        memory: 1Gi
      min:
        cpu: "50m"
        memory: 64Mi
    - type: Pod
      max:
        cpu: "4"
        memory: 2Gi
```

## 12. 자주 쓰는 kubectl 명령 (메타데이터 관련)

```bash
# 레이블 추가/수정
kubectl label pod my-pod env=prod
kubectl label pod my-pod env=staging --overwrite

# 레이블 삭제
kubectl label pod my-pod env-

# 레이블로 필터링
kubectl get pods -l app=my-app
kubectl get pods -l 'env in (prod, staging)'
kubectl get pods -l 'env notin (dev)'
kubectl get pods -l app=my-app,env=prod

# 어노테이션
kubectl annotate pod my-pod description="main app"
kubectl annotate pod my-pod description-       # 삭제

# selector로 오브젝트 확인
kubectl get pods --selector app=my-app

# 빠른 리소스 생성 (시험 팁)
kubectl run my-pod --image=nginx --dry-run=client -o yaml > pod.yaml
kubectl create deployment my-deploy --image=nginx --replicas=3 --dry-run=client -o yaml > deploy.yaml
kubectl expose pod my-pod --port=80 --target-port=8080 --dry-run=client -o yaml > svc.yaml
```
