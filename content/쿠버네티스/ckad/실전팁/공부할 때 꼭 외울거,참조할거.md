아 그 기분 완전 이해해요 😅 CKAD는 "애플리케이션 개발자용"이라고 이름이 붙어있어서 처음엔 만만해 보이는데, 파고들수록 끝이 없어 보이죠. 실제로 합격자들도 다들 그 벽을 느낍니다.

## 왜 이렇게 많아 보이는가

**쿠버네티스 자체가 "작은 운영체제" 같은 크기**라서 그래요. Pod, Deployment, Service, ConfigMap, Secret, Volume, Probe, Job, CronJob, NetworkPolicy, Ingress, PV/PVC, SA/RBAC, HPA... 리소스 종류만 20개 넘고, 각각에 세부 필드가 또 수십 개씩 있어요.

그런데 **다행인 건** CKAD는 이걸 다 외우라는 시험이 아니에요. 공식 시험 범위(2026년 기준)는 이렇게 가중치가 정해져 있어요:

| 영역                                                  | 비중  |
| --------------------------------------------------- | --- |
| Application Design and Build                        | 20% |
| Application Deployment                              | 20% |
| Application Observability and Maintenance           | 15% |
| Application Environment, Configuration and Security | 25% |
| Services and Networking                             | 20% |

보이시죠? **Configuration/Security(Secret, ConfigMap, SA)**하고 **Design(Pod, Deployment, multi-container 패턴)**이 전체의 45%예요. 지금까지 하신 ConfigMap/Secret/Volume 주입은 실제 시험 비중이 큰 부분을 공부하고 계신 거예요.

## 불필요하게 깊이 파는 함정

CKAD 공부하다 막히는 전형적 패턴:

1. **Kubernetes 내부 동작 이해하려고 함** — 예: kube-proxy, CNI, etcd 구조. **이건 CKA 범위예요. CKAD는 불필요**.
2. **Helm, CRD, Operator까지 손댐** — 시험에 안 나옵니다. 2026년 1월 합격 후기에서도 *"CRD, Helm, PVC/PV 관련 문제 0개 나왔다"*는 얘기가 있었어요.
3. **모든 리소스의 모든 필드 외우려 함** — 시험은 docs 참조 허용이에요. **외우는 게 아니라 "어디에 뭐가 있는지 아는 것"**이 핵심.

## 실제로 외워야 할 것은 생각보다 적음

제가 시험 관점에서 압축하면 이 정도예요:

### 반드시 손에 붙여야 하는 것 (시험 시간 때문에)

- `kubectl run/create/expose`의 imperative 명령어 10개 정도 [[kubectl run create expose의 imperative 명령어|(link)]]
- `--dry-run=client -o yaml > file.yaml` 패턴
- Pod YAML 기본 구조 (지금 하신 거)
- volumeMounts + volumes 연결 구조 [[volume 패턴|(link)]]
- env / envFrom / valueFrom 차이 [[env envFrom valueFrom 차이|(link)]]
- `-l` selector, `-n` namespace

### 패턴만 알아두면 되는 것 (docs에서 복붙)

- multi-container 패턴 (sidecar, init container)
- Probe (liveness, readiness, startup) [[2. Readiness vs Liveness Probe|(link)]]
- SecurityContext
- NetworkPolicy
- ServiceAccount + Role + RoleBinding
- Job / CronJob spec
- HPA

### 개념만 알면 되는 것 (직접 만들 일 거의 없음)

- PV/PVC의 관계 (Pod에서 쓰기만 하면 됨)
- Ingress 구조 [[2. ingress, egress|(link)]]
- Resource Quota, LimitRange

## 공부 전략 제안

지금까지 하신 거 보면 이미 **개념은 많이 잡히셨어요**. 에러 만나고 고치면서 배우신 거(Pod immutable, YAML 들여쓰기, envFrom vs env)는 실전 경험이에요. 이게 단순 암기보다 훨씬 가치 있습니다.

**다음 단계로는 이 순서를 추천해요:**

1. **killer.sh 시뮬레이터 한 번 풀어보기** 시험 등록하면 2번 세션 무료로 제공돼요. 실제 시험보다 어렵지만, "내가 뭘 모르는지" 정확히 알게 됩니다. 합격자들이 입을 모아 강추하는 이유예요.
    
2. **kubectl 치트시트 한 번 쭉 훑기** 공식 docs의 `kubectl Cheat Sheet` 페이지. 시험장에서 열어둘 수 있으니 "어떤 명령어가 있는지"만 인지해두면 됨. [[쿠버네티스/Kubernetes-Cheat-Sheet/README|(link)]]
    
3. **실수 노트 만들기** 지금까지 만나신 에러들 (Pod immutable, YAML 들여쓰기, envFrom 구조 등)은 **시험에서 또 만날** 거예요. 간단히 메모해두면 반복 실수 안 합니다.
    

## Go 개발자 관점 한마디

Go 백엔드 개발자시면 이미 이런 경험 있으실 거예요: **"standard library가 크긴 한데, 실제로 매일 쓰는 건 10개 정도"**. CKAD도 똑같아요. 시험 범위는 넓게 공지돼 있지만 **실전에서 반복되는 패턴은 생각보다 적습니다**.

지금처럼 하나씩 에러 만나고 이해하면서 가시는 방식이 정답이에요. 한꺼번에 다 외우려고 하면 번아웃 오고, 정작 시험에서 실수합니다.

## 현실적인 격려

- 시험은 **66% 합격**이에요. 100점 맞을 필요 없음.
- **부분 점수**가 있어서 절반만 맞춰도 점수 나옴.
- **재시험 1회 무료** (registration에 포함돼 있음).
- 합격자들 평균 준비 기간은 **20~60시간** 정도예요. 끝이 있는 싸움이에요.
