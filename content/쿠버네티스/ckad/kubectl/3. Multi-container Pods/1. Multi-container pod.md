### 1. Multi-container Pod이란

같은 Pod 안의 여러 컨테이너는 다음을 공유합니다.

- **네트워크**: 같은 IP, 같은 포트 공간 → `localhost`로 통신
- **볼륨**: 같은 volume을 mount하면 파일 공유 가능
- **생명주기**: 함께 시작되고 함께 종료

공유하지 않는 것:

- **파일시스템**: 각 컨테이너는 독립된 파일시스템 (볼륨 mount 외에는)
- **프로세스**: 각자 PID 1

이 특성을 활용해서 메인 컨테이너 옆에 보조 컨테이너를 두는 게 multi-container 패턴의 본질입니다.

### 2. 언제 Multi-container를 쓰는가

**한 Pod에 묶어야 할 때**:

- 두 컨테이너가 **항상 같은 노드에서 함께 살아야** 할 때
- 강하게 결합되어 있어 **개별 스케일링이 필요 없을** 때
- 같은 볼륨이나 네트워크를 **반드시 공유**해야 할 때

**별도 Pod으로 분리해야 할 때**:

- 독립적으로 스케일링하고 싶을 때
- 다른 노드에서도 동작 가능해야 할 때
- 라이프사이클이 다를 때

판단 기준: "이 둘이 떨어져 살 수 있나?" 답이 No면 한 Pod, Yes면 분리.

### 3. 4가지 디자인 패턴

#### Sidecar 패턴

메인 컨테이너의 기능을 **확장하거나 보조**. 가장 흔한 패턴.

**용도**: 로그 수집, 파일 동기화, 동적 콘텐츠 생성, 프록시

yaml

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-with-logger
spec:
  containers:
  - name: web
    image: nginx
    volumeMounts:
    - name: logs
      mountPath: /var/log/nginx
  - name: log-shipper           # Sidecar
    image: busybox
    command: ["sh", "-c", "tail -f /logs/access.log"]
    volumeMounts:
    - name: logs
      mountPath: /logs
  volumes:
  - name: logs
    emptyDir: {}
```

#### Adapter 패턴

메인 컨테이너의 출력을 **외부 시스템이 이해할 수 있는 형식으로 변환**.

**용도**: 로그 포맷 변환, 메트릭 표준화

yaml

```yaml
spec:
  containers:
  - name: app
    image: my-app
    volumeMounts:
    - name: shared
      mountPath: /var/log
  - name: adapter               # Adapter
    image: log-converter
    command: ["sh", "-c", "convert /raw/app.log > /standard/output.log"]
    volumeMounts:
    - name: shared
      mountPath: /raw
```

Sidecar와 비슷하지만, Adapter는 **변환에 집중**합니다.

#### Ambassador 패턴

메인 컨테이너 **대신 외부와 통신**. 메인은 항상 `localhost`로만 접근.

**용도**: 외부 서비스 프록시, 인증 토큰 관리, 연결 풀링

```yaml
spec:
  containers:
  - name: app
    image: my-app
    env:
    - name: DB_HOST
      value: "localhost"        # 항상 localhost로 접근
    - name: DB_PORT
      value: "6379"
  - name: ambassador            # Ambassador
    image: redis-proxy
    ports:
    - containerPort: 6379
    # 외부 redis로 연결 처리
```

메인 컨테이너는 외부 주소를 몰라도 됩니다. Ambassador가 외부 환경별 차이를 흡수.

#### Init Container 패턴

메인 컨테이너 시작 **전에** 실행되어 완료되어야 하는 컨테이너. `containers` 배열이 아닌 **`initContainers` 배열**에 정의.

**용도**: 의존 서비스 대기, 설정/데이터 준비, 권한 설정

```yaml
spec:
  initContainers:
  - name: wait-for-db
    image: busybox
    command: ["sh", "-c", "until nslookup db; do sleep 2; done"]
  - name: prepare-config
    image: busybox
    command: ["sh", "-c", "echo 'ready' > /config/status"]
    volumeMounts:
    - name: config
      mountPath: /config
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: config
      mountPath: /etc/config
  volumes:
  - name: config
    emptyDir: {}
```

**Init container의 특징**:

- **순차 실행**: 위에서 아래로 하나씩
- **모두 성공해야** 메인 컨테이너 시작
- 실패 시 `restartPolicy`에 따라 재시도
- 메인이 시작되면 init은 더 이상 실행 안 됨

### 4. 4가지 패턴 비교

|패턴|위치|실행 시점|주 용도|
|---|---|---|---|
|Sidecar|`containers`|메인과 동시|보조 기능 추가|
|Adapter|`containers`|메인과 동시|출력 변환|
|Ambassador|`containers`|메인과 동시|외부 통신 대리|
|Init|`initContainers`|메인 시작 전|초기화|

Sidecar/Adapter/Ambassador는 모두 같은 `containers` 배열에 들어가는 **병렬 실행** 컨테이너이고, 역할에 따라 이름만 다르게 부릅니다. Init만 별도 배열입니다.

### 5. 컨테이너 간 통신 방법

#### 방법 1: localhost 통신 (네트워크 공유)

같은 Pod 안의 컨테이너끼리는 `localhost`로 통신합니다.

```yaml
spec:
  containers:
  - name: app
    image: my-app
    env:
    - name: CACHE_URL
      value: "localhost:6379"   # 같은 Pod의 redis
  - name: redis
    image: redis
    ports:
    - containerPort: 6379
```

**주의**: 같은 Pod 안에서는 **포트가 충돌하면 안 됨**. 두 컨테이너가 같은 포트를 listen할 수 없음.

#### 방법 2: 공유 볼륨 (파일 공유)

```yaml
spec:
  containers:
  - name: writer
    image: busybox
    command: ["sh", "-c", "while true; do echo $(date) > /data/time.txt; sleep 5; done"]
    volumeMounts:
    - name: shared
      mountPath: /data
  - name: reader
    image: busybox
    command: ["sh", "-c", "while true; do cat /data/time.txt; sleep 5; done"]
    volumeMounts:
    - name: shared
      mountPath: /data
  volumes:
  - name: shared
    emptyDir: {}
```

`emptyDir`이 가장 흔히 사용됩니다. Pod이 살아있는 동안만 유지.

### 6. 컨테이너 로그 확인

```bash
# 단일 컨테이너 Pod
k logs my-pod

# Multi-container Pod (컨테이너 이름 지정 필수)
k logs my-pod -c web
k logs my-pod -c sidecar

# 모든 컨테이너 로그
k logs my-pod --all-containers

# Init container 로그
k logs my-pod -c init-db

# 이전(크래시 전) 로그
k logs my-pod -c sidecar --previous
```

Multi-container Pod에서 `-c`를 빼면 `error: a container name must be specified` 에러가 납니다.

### 7. 컨테이너 접속

```bash
# 특정 컨테이너에 접속
k exec -it my-pod -c sidecar -- sh

# 명령 실행
k exec my-pod -c sidecar -- ls /data

# 기본 컨테이너 (배열의 첫 번째)
k exec -it my-pod -- sh
```
