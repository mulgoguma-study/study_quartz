## Multi-container Pods 시험 팁

### 시작 세팅

```bash
alias k=kubectl
export do="--dry-run=client -o yaml"
export now="--grace-period=0 --force"
```

### 자주 쓰는 YAML 생성 명령

Multi-container Pod은 **imperative 명령으로 한 번에 생성 불가능**합니다. 단일 컨테이너 Pod의 골격을 만들고 두 번째 컨테이너부터 YAML에 직접 추가하는 게 표준 방법입니다.

```bash
# 1단계: 단일 컨테이너 Pod 골격 생성
k run my-pod --image=nginx $do > pod.yaml

# 2단계: 두 번째 컨테이너, init container, volume을 YAML에 추가

# 3단계: 적용
k apply -f pod.yaml
```

#### 빈 템플릿 (외워둘 것)

**Sidecar 패턴 템플릿**:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
  - name: main
    image: nginx
    volumeMounts:
    - name: shared
      mountPath: /var/log/nginx
  - name: sidecar
    image: busybox
    command: ["sh", "-c", "tail -f /logs/access.log"]
    volumeMounts:
    - name: shared
      mountPath: /logs
  volumes:
  - name: shared
    emptyDir: {}
```

**Init container 템플릿**:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  initContainers:
  - name: init
    image: busybox
    command: ["sh", "-c", "until nslookup db; do sleep 2; done"]
  containers:
  - name: main
    image: nginx
```


### explain으로 확인할 필드

```bash
# Init container 위치 확인용
k explain pod.spec.initContainers
k explain pod.spec.initContainers --recursive | less

# Container 필드
k explain pod.spec.containers --recursive | less

# Volume 종류
k explain pod.spec.volumes --recursive | less

# 가장 헷갈리는 필드들
k explain pod.spec.containers.volumeMounts
k explain pod.spec.containers.lifecycle
```


### 자주 헷갈리는 차이 정리

|항목|containers|initContainers|
|---|---|---|
|실행 시점|Pod 시작 후 병렬|Pod 시작 시 순차|
|모두 성공해야?|아님 (각자 동작)|모두 성공 후 메인 시작|
|종료 후|계속 실행|한 번 끝나고 종료 상태|
|로그 확인|`k logs -c <name>`|`k logs -c <name>` (같음)|
|재시작|restartPolicy에 따라|restartPolicy에 따라 재시도|

|패턴|메인과의 관계|위치|
|---|---|---|
|Sidecar|보조 (확장)|`containers`|
|Adapter|변환|`containers`|
|Ambassador|외부 통신 대리|`containers`|
|Init|사전 준비|`initContainers`|

|Volume 종류 (multi-container 공유용)|특징|
|---|---|
|`emptyDir: {}`|가장 흔함, Pod 생명주기|
|`emptyDir: {medium: Memory}`|메모리 기반 (tmpfs)|
|`configMap`|읽기 전용 설정 공유|
|`persistentVolumeClaim`|영구 저장|

|Pod 상태|의미|
|---|---|
|`Init:0/2`|init container 진행 중 (0/2 완료)|
|`Init:Error`|init container 실패|
|`Init:CrashLoopBackOff`|init이 반복 크래시|
|`PodInitializing`|init 완료, 메인 시작 직전|
|`Running 1/2`|컨테이너 중 하나만 정상|
|`Running 2/2`|모든 컨테이너 정상|

---

Multi-container Pod은 **YAML 직접 작성 비중이 큰 영역**입니다. Sidecar 템플릿과 Init container 템플릿을 손으로 외워서 빈 종이에 그릴 수 있을 정도로 익혀두면 시간 절약이 큽니다. 특히 `volumeMounts`-`volumes`의 name 일치, init container의 별도 배열 위치, multi-container logs의 `-c` 옵션 이 세 가지는 가장 자주 실수하는 부분이니 시험 직전에 반드시 한 번 더 복습하세요.
