`Role / RoleBinding / ClusterRole / ClusterRoleBinding. 
`Role은 namespace 범위, ClusterRole은 클러스터 전체 범위입니다.

```bash
# Role 생성 (가장 많이 쓰는 명령)
kubectl create role pod-reader \
  --verb=get,list,watch \
  --resource=pods \
  -n dev

# RoleBinding (SA와 Role 연결)
kubectl create rolebinding pod-reader-binding \
  --role=pod-reader \
  --serviceaccount=dev:my-sa \
  -n dev

# ClusterRole
kubectl create clusterrole node-reader \
  --verb=get,list \
  --resource=nodes

# ClusterRoleBinding
kubectl create clusterrolebinding node-reader-binding \
  --clusterrole=node-reader \
  --serviceaccount=dev:my-sa
```


**권한 확인 명령** (시험에서 검증할 때 유용):

```bash
kubectl auth can-i get pods --as=system:serviceaccount:dev:my-sa -n dev
kubectl auth can-i create deployments --as=system:serviceaccount:dev:my-sa
```

`--as=system:serviceaccount:<namespace>:<sa-name>` 형식을 외워두세요.

**출제 패턴**: "SA를 만들고, 특정 리소스에 특정 verb 권한만 부여하라. auth can-i로 검증하라." `verb`로는 보통 get/list/watch/create/update/delete/patch가 나옵니다.
