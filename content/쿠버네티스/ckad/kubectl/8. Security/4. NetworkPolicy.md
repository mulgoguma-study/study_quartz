이게 Security에서 가장 까다롭고 출제 빈도도 높습니다.

yaml

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend
  namespace: prod
spec:
  podSelector:
    matchLabels:
      app: backend       # 이 정책이 적용될 대상 Pod
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend
    - namespaceSelector:
        matchLabels:
          env: prod
    ports:
    - protocol: TCP
      port: 8080
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: database
    ports:
    - protocol: TCP
      port: 5432
```

함정 포인트가 두 가지 있습니다:

**함정 1**: `from` 아래에 `-`(dash)가 여러 개면 OR, 한 항목 안에 여러 selector를 쓰면 AND입니다.

yaml

```yaml
# OR: frontend Pod 이거나 prod namespace의 모든 Pod
- from:
  - podSelector:
      matchLabels:
        app: frontend
  - namespaceSelector:
      matchLabels:
        env: prod

# AND: prod namespace의 frontend Pod만
- from:
  - namespaceSelector:
      matchLabels:
        env: prod
    podSelector:
      matchLabels:
        app: frontend
```

이 차이를 묻는 문제가 자주 나옵니다.

**함정 2**: `policyTypes`에 Egress가 없으면 egress 규칙은 무시됩니다. 명시적으로 적어야 합니다.

**출제 패턴**: "frontend namespace의 Pod만 backend Pod의 80 포트로 접근 가능하게 하라. 그 외 모든 트래픽은 차단." DNS(53/UDP)도 허용해야 하는 함정이 자주 있습니다.
