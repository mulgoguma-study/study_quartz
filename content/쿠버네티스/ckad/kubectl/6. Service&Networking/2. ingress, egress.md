네, NetworkPolicy 파트에서 나오는데 **헷갈리기 쉬워서 틀리기 쉬운 파트**예요.

Networkpolicy는 따로 kubectl create로 imperative하게 만드는 명령어는 없고 그냥 yaml 직접 작성해서 apply 하는 방법뿐임.
k8s는 기본이 모든 pod간 통신이 허용된거라 일부러 막는 계념임


CKAD 시험 중 `kubernetes.io/docs` 탭 열어서 검색 .

**실제 시험 플로우:**

1. 브라우저에서 `kubernetes.io/docs` 열기
2. `NetworkPolicy` 검색
3. 예제 yaml 복사
4. 터미널에서 `vi netpol.yaml` 열고 붙여넣기
5. 필요한 부분만 수정 (이름, 라벨, 포트 등)
6. `kubectl apply -f netpol.yaml`

**그래서 외워야 할 건 yaml 전체가 아니라:**

- `podSelector`, `ingress.from`, `egress.to` 구조 이해

---

## NetworkPolicy 기본 개념

기본적으로 K8s는 모든 Pod 간 통신이 허용됩니다. NetworkPolicy로 허용할 트래픽을 명시적으로 지정하는 방식입니다.

```
Ingress = 들어오는 트래픽 (inbound)
Egress  = 나가는 트래픽 (outbound)
```

---

## 예시 문제 유형

보통 이런 식으로 나옵니다.

> "db Pod는 backend Pod에서 오는 트래픽만 허용하고 나머지는 차단하라"

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: db-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      role: db          # 이 정책을 적용할 Pod
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          role: backend  # backend Pod에서 오는 트래픽만 허용
    ports:
    - protocol: TCP
      port: 3306
```

---

## 헷갈리는 포인트

**`from` 배열에서 `-` 위치가 핵심입니다.**

```yaml
# AND 조건 (같은 - 아래)
# backend label이고 AND prod namespace인 Pod만 허용
ingress:
- from:
  - podSelector:
      matchLabels:
        role: backend
    namespaceSelector:
      matchLabels:
        env: prod

# OR 조건 (- 가 분리됨)
# backend label이거나 OR prod namespace면 허용
ingress:
- from:
  - podSelector:
      matchLabels:
        role: backend
  - namespaceSelector:
      matchLabels:
        env: prod
```

시험에서 이 차이로 틀리는 경우가 많아요.

---

## Egress 예시

```yaml
spec:
  podSelector:
    matchLabels:
      role: backend
  policyTypes:
  - Egress
  egress:
  - to:
    - podSelector:
        matchLabels:
          role: db
    ports:
    - protocol: TCP
      port: 3306
```

---

## Ingress + Egress 동시 적용

```yaml
policyTypes:
- Ingress
- Egress
ingress:
- from: ...
egress:
- to: ...
```

`policyTypes`에 명시한 타입만 제한됩니다. `Ingress`만 적으면 Egress는 여전히 전부 허용.

## 시험 출제 빈도

```
NetworkPolicy (Ingress/Egress)   ★★★★
```

어렵진 않지만 `-` 위치 실수, `policyTypes` 누락으로 틀리는 경우가 많아서 꼼꼼히 연습해두는 게 좋습니다.

## 빠른 디버깅

```bash
kubectl get networkpolicy
kubectl describe networkpolicy db-policy

# 특정 Pod의 label 확인
kubectl get pod db-pod --show-labels
```

NetworkPolicy는 `kubectl create`로 뼈대 생성이 안 돼서 yaml을 직접 써야 합니다. 구조 외워두는 게 좋아요.


NetworkPolicy 문제 자체가 결국 "어떤 Pod에서 어떤 Pod로의 트래픽을 허용/차단하라" 이거라서, 풀어보면 항상 ingress/egress 설정 문제입니다.

세부적으로 나오는 변형은 이 정도예요.

- `podSelector`만 쓰는 경우 (같은 namespace 내 Pod 간 제한)
- `namespaceSelector` 추가 (다른 namespace에서 오는 트래픽 제한)
- 둘을 AND/OR 조합하는 경우 (아까 말한 `-` 위치 문제)
- 특정 port만 허용하는 경우
- Ingress + Egress 동시 적용

구조 자체는 단순한데 yaml 직접 써야 하고 `-` 위치 하나로 의미가 달라지다 보니 실수가 나오는 파트예요. 구조 한 번 손으로 써보면서 익혀두면 시험장에서 빠르게 칠 수 있습니다.
