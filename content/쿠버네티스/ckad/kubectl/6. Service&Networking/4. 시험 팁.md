## Service & Networking 시험 팁

### 시작 세팅

```bash
alias k=kubectl
export do="--dry-run=client -o yaml"
export now="--grace-period=0 --force"
```

### 자주 쓰는 YAML 생성 명령

#### Service

```bash
# Deployment를 노출 (가장 빠른 방법)
k expose deploy web --port=80 --target-port=8080
k expose deploy web --port=80 --target-port=8080 --type=NodePort
k expose deploy web --port=80 --target-port=8080 --type=LoadBalancer

# 이름 다르게 지정
k expose deploy web --name=web-svc --port=80 --target-port=8080

# Pod 직접 노출
k expose pod my-pod --port=80 --target-port=8080

# 명령어로 직접 Service 생성
k create svc clusterip my-svc --tcp=80:8080
k create svc nodeport my-svc --tcp=80:8080 --node-port=30080
k create svc loadbalancer my-svc --tcp=80:8080
k create svc externalname my-svc --external-name=api.example.com

# YAML로 출력
k expose deploy web --port=80 --target-port=8080 $do > svc.yaml
k create svc clusterip my-svc --tcp=80:8080 $do > svc.yaml
```


#### Ingress


```bash
# Ingress (1.19+)
k create ingress my-ing --rule="example.com/api*=api-svc:80"

# 여러 경로
k create ingress my-ing \
  --rule="example.com/api*=api-svc:80" \
  --rule="example.com/web*=web-svc:80"

# TLS 포함
k create ingress my-ing \
  --rule="example.com/*=web-svc:80,tls=tls-secret"

# IngressClass 지정
k create ingress my-ing \
  --class=nginx \
  --rule="example.com/*=web-svc:80"

# YAML로 출력
k create ingress my-ing --rule="example.com/api*=api-svc:80" $do > ing.yaml
```

`--rule`의 `*` 표시는 Prefix, 없으면 Exact.

#### NetworkPolicy

NetworkPolicy는 imperative 명령이 없습니다. **반드시 YAML 직접 작성**.

빈 템플릿을 미리 외워두세요:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: my-policy
spec:
  podSelector:
    matchLabels:
      app: target
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: source
    ports:
    - protocol: TCP
      port: 80
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: dest
    ports:
    - protocol: TCP
      port: 5432
```

### explain으로 확인할 필드

```bash
# Service
k explain svc.spec --recursive | less
k explain svc.spec.ports

# Ingress
k explain ingress.spec --recursive | less
k explain ingress.spec.rules.http.paths.backend

# NetworkPolicy (가장 자주 explain 필요)
k explain networkpolicy.spec --recursive | less
k explain networkpolicy.spec.ingress.from
k explain networkpolicy.spec.egress.to
```

NetworkPolicy의 필드명이 가장 헷갈리므로 explain을 적극 활용하세요.


### 디버깅 명령

```bash
# Service 상태
k get svc
k get svc -o wide
k describe svc my-svc

# Endpoints (Pod 연결 확인)
k get ep my-svc
k get ep my-svc -o yaml

# Pod에서 Service로 테스트
k run tmp --image=busybox --rm -it --restart=Never -- wget -O- my-svc:80
k run tmp --image=busybox --rm -it --restart=Never -- nslookup my-svc

# Service의 DNS 확인
k run tmp --image=busybox --rm -it --restart=Never -- \
  nslookup my-svc.default.svc.cluster.local

# Ingress
k get ing
k describe ing my-ing

# NetworkPolicy
k get netpol
k describe netpol my-policy

# 라벨 확인 (selector 매칭용)
k get pod --show-labels
k get pod -l app=web

# Port forwarding (디버깅용)
k port-forward svc/my-svc 8080:80
k port-forward pod/my-pod 8080:80
```

### 빠르게 작성하는 팁

- **Service는 99% `k expose`로 생성**. YAML 직접 안 씀. 만든 뒤 `k get ep`로 확인하는 습관.
- **Ingress는 `k create ingress`로 골격 생성** 후 `--rule` 문법으로 빠르게. 1.19+ 시험 환경에서는 충분.
- **NetworkPolicy는 YAML 직접 작성**. `k explain --recursive`로 필드 확인하며 작성. 빈 템플릿을 외워두면 시간 절약.
- **Service 만든 직후 항상 검증**: `k get svc`, `k get ep`, 임시 Pod으로 curl/wget. 이 3단계가 디폴트.
- **NetworkPolicy 디버깅**: 정책 적용 후 임시 Pod으로 통신 테스트. 막혀야 하는 곳이 막혔는지, 허용되어야 하는 곳이 허용되는지 양방향 확인.
- **DNS 테스트용 Pod**:

```bash
  k run tmp --image=busybox --rm -it --restart=Never -- nslookup my-svc
```

- **모든 namespace의 Service 보기**: `k get svc -A`

### 자주 헷갈리는 차이 정리

|항목|ClusterIP|NodePort|LoadBalancer|ExternalName|
|---|---|---|---|---|
|외부 접근|❌|✅ (NodeIP:port)|✅ (LB IP)|❌ (DNS만)|
|가상 IP|✅|✅|✅|❌|
|포트 범위|임의|30000-32767|임의|없음|
|클라우드 필요|❌|❌|✅|❌|

|항목|Service|Ingress|
|---|---|---|
|계층|L4 (TCP/UDP)|L7 (HTTP/HTTPS)|
|라우팅 기준|포트|호스트/경로|
|TLS 종료|❌|✅|
|여러 백엔드|❌|✅|
|컨트롤러 필요|❌|✅ (nginx 등)|

|항목|port|targetPort|nodePort|
|---|---|---|---|
|위치|Service|Pod|Node|
|누가 사용|클러스터 내 클라이언트|컨테이너|외부 클라이언트|
|범위|임의|임의|30000-32767|

|항목|NetworkPolicy 빈 객체|생략|
|---|---|---|
|`podSelector: {}`|모든 Pod|(위치에 따라 다름)|
|`from: []`|트래픽 차단|모두 허용|
|`policyTypes` 빈 배열|모두 차단|spec에서 추론|

---

Service & Networking은 **명령어로 빠른 생성 + 디버깅 흐름 숙달**이 핵심입니다. 특히 Service의 selector-label 일치와 NetworkPolicy의 AND/OR 차이는 시험 직전에 반드시 한 번 더 복습하세요. NetworkPolicy의 빈 템플릿을 손으로 외워두면 시간 절약 효과가 매우 큽니다.
