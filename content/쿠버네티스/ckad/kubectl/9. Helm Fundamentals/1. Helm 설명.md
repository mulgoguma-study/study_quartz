CKAD에서 Helm은 약 2% 정도로 비중이 작지만, 출제되면 거의 정형화된 패턴으로 나오기 때문에 명령어 몇 개만 익히면 점수를 확보할 수 있는 영역입니다.

1. Helm이란
Helm은 Kubernetes의 패키지 매니저입니다. apt나 npm처럼 애플리케이션을 패키지 단위로 설치/업그레이드/삭제할 수 있게 해줍니다.

핵심 용어 세 가지를 먼저 외우세요.

- **Chart**: Kubernetes 리소스들을 묶은 패키지 (YAML 템플릿 모음)
- **Repository**: Chart들을 모아둔 저장소
- **Release**: 클러스터에 설치된 Chart의 인스턴스. 같은 Chart도 이름만 다르면 여러 번 설치 가능

비유하자면 Chart는 클래스, Release는 인스턴스라고 보면 됩니다.

### 2. Chart 구조

```
mychart/
├── Chart.yaml          # 차트 메타데이터 (이름, 버전, 설명)
├── values.yaml         # 기본 설정값
├── charts/             # 의존하는 sub-chart
└── templates/          # Kubernetes 리소스 YAML 템플릿
    ├── deployment.yaml
    ├── service.yaml
    └── _helpers.tpl
```

`Chart.yaml` 예시:

yaml

```yaml
apiVersion: v2
name: mychart
description: A Helm chart for Kubernetes
type: application
version: 0.1.0          # Chart 버전
appVersion: "1.16.0"    # 애플리케이션 버전
```

CKAD에서는 Chart를 직접 만들 일은 거의 없고, **기존 Chart를 설치/업그레이드/삭제하는** 작업이 대부분입니다.

### 3. Repository 관리

bash

```bash
# 리포지토리 추가
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo add stable https://charts.helm.sh/stable

# 리포지토리 목록
helm repo list

# 리포지토리 인덱스 업데이트 (최신 chart 정보 가져오기)
helm repo update

# 리포지토리 삭제
helm repo remove bitnami
```

`helm repo add` 후에 **반드시 `helm repo update`** 를 해야 최신 chart 정보를 가져옵니다. 시험에서 빼먹기 쉬운 단계입니다.

### 4. Chart 검색

bash

```bash
# 로컬에 추가된 리포지토리에서 검색
helm search repo nginx
helm search repo bitnami/nginx

# Artifact Hub에서 검색 (인터넷 전체)
helm search hub wordpress

# 버전 정보 포함
helm search repo nginx --versions
```

`search repo`는 로컬 캐시, `search hub`는 외부 hub 전체 검색입니다.

### 5. Chart 설치 (가장 중요)

bash

```bash
# 기본 설치
helm install my-release bitnami/nginx

# 특정 namespace에 설치
helm install my-release bitnami/nginx -n web --create-namespace

# values 덮어쓰기 (CLI)
helm install my-release bitnami/nginx \
  --set replicaCount=3 \
  --set service.type=NodePort

# values 파일로 덮어쓰기
helm install my-release bitnami/nginx -f custom-values.yaml

# 특정 버전 설치
helm install my-release bitnami/nginx --version 13.2.0

# 설치 전에 렌더링만 미리 보기 (dry-run)
helm install my-release bitnami/nginx --dry-run --debug
```

`--set`은 점 표기법으로 중첩 값을 덮어씁니다. `service.type=NodePort`는 `values.yaml`의 `service: type: NodePort`와 같습니다.

### 6. Release 관리

bash

```bash
# 설치된 Release 목록
helm list                  # 현재 namespace
helm list -A               # 전체 namespace
helm list -n web

# Release 상태 확인
helm status my-release

# Release의 values 확인
helm get values my-release        # 사용자가 변경한 값만
helm get values my-release --all  # 모든 값 (기본값 포함)

# Release가 만든 리소스 확인
helm get manifest my-release
```

### 7. Upgrade & Rollback

bash

```bash
# 업그레이드
helm upgrade my-release bitnami/nginx --set replicaCount=5

# 설치되어 있지 않으면 install, 있으면 upgrade
helm upgrade --install my-release bitnami/nginx

# Release 히스토리
helm history my-release

# 이전 버전으로 롤백 (revision 번호 지정)
helm rollback my-release 1
```

`upgrade --install` 패턴은 CI/CD에서 자주 쓰입니다.

### 8. Release 삭제

bash

```bash
# Release 삭제 (히스토리는 남김)
helm uninstall my-release

# Release 완전 삭제 (히스토리도 제거)
helm uninstall my-release --keep-history=false
```

### 9. Chart 다운로드 (Pull)

bash

```bash
# Chart를 tar.gz로 다운로드
helm pull bitnami/nginx

# 다운로드 후 압축 해제
helm pull bitnami/nginx --untar

# 특정 버전 다운로드
helm pull bitnami/nginx --version 13.2.0 --untar
```

values.yaml을 확인하거나 수정해서 사용할 때 자주 씁니다.

### 10. Template 렌더링 (검증용)

bash

```bash
# Chart를 실제로 설치하지 않고 YAML로 렌더링만
helm template my-release bitnami/nginx
helm template my-release bitnami/nginx --set replicaCount=3

# 특정 파일만
helm template my-release bitnami/nginx -s templates/deployment.yaml
```

설치 전에 어떤 리소스가 생성될지 미리 확인할 때 유용합니다.
