### 시작 세팅

```bash
alias h=helm
```

특별한 환경변수는 없습니다. `kubectl`과 달리 `--dry-run -o yaml` 같은 패턴도 거의 안 쓰고, **명령어가 곧 답**입니다.

### 자주 쓰는 명령 요약

```bash
# Repository
helm repo add <name> <url>
helm repo update
helm repo list
helm repo remove <name>

# Search
helm search repo <keyword>
helm search repo <keyword> --versions
helm search hub <keyword>

# Install
helm install <release-name> <chart>
helm install <release-name> <chart> --version <ver>
helm install <release-name> <chart> --set key=value
helm install <release-name> <chart> -f values.yaml
helm install <release-name> <chart> -n <ns> --create-namespace

# List / Inspect
helm list -A
helm status <release>
helm get values <release>
helm get values <release> --all
helm get manifest <release>

# Upgrade / Rollback
helm upgrade <release> <chart> --set key=value
helm upgrade --install <release> <chart>
helm history <release>
helm rollback <release> <revision>

# Uninstall
helm uninstall <release>

# Pull / Template
helm pull <chart> --untar
helm pull <chart> --version <ver> --untar
helm template <release> <chart>
```

### 도움말 확인 명령 (시험장에서 유용)

```bash
helm --help
helm install --help
helm upgrade --help
helm search --help
```

man 페이지 보듯이 `--help`로 옵션을 빠르게 확인할 수 있습니다. Helm 명령은 옵션이 많지 않아서 `--help`만 봐도 답이 나옵니다.

### 출제 패턴

크게 네 가지 유형으로 정형화되어 있습니다.

**유형 1: Repository 추가 후 Chart 설치** (가장 자주 출제) "bitnami 리포지토리를 추가하고, nginx chart를 my-release 이름으로 설치하라."

- `repo add` → `repo update` → `install` 순서를 빼먹지 않기.

**유형 2: 특정 버전 또는 values로 설치** "replicaCount를 3으로, service.type을 NodePort로 설정해서 설치하라."

- `--set` 또는 `-f values.yaml` 사용.

**유형 3: Chart 다운로드 후 values 확인/수정** "chart를 pull해서 압축 해제하고, values.yaml을 수정한 뒤 그 값으로 설치하라."

- `helm pull --untar` → values.yaml 편집 → `helm install -f`.

**유형 4: 기존 Release 업그레이드 또는 삭제** "my-release의 replicaCount를 5로 업그레이드하라" 또는 "old-release를 삭제하라."

### 함정 포인트

**함정 1 — `helm repo update` 빼먹기** `repo add` 후 바로 `install`하면 chart를 못 찾는 경우가 있습니다. **반드시 update를 사이에 넣기.**

**함정 2 — Release 이름과 Chart 이름 순서**

```bash
helm install <release-name> <chart>   # 순서 주의
```

`helm install bitnami/nginx my-release` 같이 거꾸로 쓰면 안 됩니다. Release 이름이 먼저.

**함정 3 — namespace 누락** `-n <namespace>`를 빼면 default namespace에 설치됩니다. 문제에서 특정 namespace를 지정하면 `--create-namespace`도 같이 챙기기.

**함정 4 — `--set`의 점 표기법** 중첩된 값은 점으로 구분: `service.type=NodePort`. 배열은 대괄호: `--set ingress.hosts[0].name=example.com`. 복잡하면 `-f values.yaml`이 더 안전.

**함정 5 — Chart 버전과 App 버전 혼동**

- `--version`은 **Chart 버전** (`Chart.yaml`의 `version`)
- `--app-version`은 거의 안 씀 문제에서 "버전 13.2.0으로 설치"라고 하면 Chart 버전을 의미.

**함정 6 — `helm list`는 기본적으로 현재 namespace만** 다른 namespace의 release를 찾을 땐 `-A` 또는 `-n <namespace>` 추가.

### 디버깅 명령

```bash
# 설치 전에 어떤 리소스가 생성될지 확인
helm install my-release bitnami/nginx --dry-run --debug

# 이미 설치된 Release의 실제 manifest 확인
helm get manifest my-release

# 현재 values 확인
helm get values my-release --all
```

### 빠르게 작성하는 팁

- Helm 명령은 **순서가 정해져 있습니다**: `repo add` → `repo update` → `search` → `install`. 이 흐름을 통째로 외우기.
- `--set` 여러 개 쓰는 것보다 `-f values.yaml`이 가독성/실수 방지 면에서 유리. 시험에선 values 수정 문제가 자주 나옵니다.
- `helm pull --untar`로 chart를 받아서 `values.yaml`을 직접 확인하는 습관. 어떤 키가 있는지 모를 때 가장 빠른 방법.
- 명령어가 헷갈리면 무조건 `helm <command> --help`. Helm은 옵션이 많지 않아서 도움말이 짧고 명확합니다.
- Release 이름은 namespace 내에서 유일해야 함. 같은 이름으로 재설치하면 에러.
