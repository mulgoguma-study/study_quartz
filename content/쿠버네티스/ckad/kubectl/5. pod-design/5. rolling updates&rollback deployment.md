## Rolling Updates & Rollback

### 개념 먼저

```
Rolling Update = Pod를 한번에 다 죽이지 않고 순차적으로 교체
Rollback       = 이전 버전으로 되돌리기
```

```
v1 v1 v1 v1
      ↓ 업데이트
v2 v1 v1 v1
v2 v2 v1 v1
v2 v2 v2 v1
v2 v2 v2 v2   ← 무중단 배포
```

---

### 핵심 명령어

**업데이트**

```bash
# 이미지 변경 (가장 많이 씀)
kubectl set image deployment/my-deploy nginx=nginx:1.19

# yaml 편집
kubectl edit deployment my-deploy

# 확인
kubectl rollout status deployment/my-deploy
```

**히스토리**

```bash
# 배포 히스토리 보기
kubectl rollout history deployment/my-deploy

# 특정 버전 상세 보기
kubectl rollout history deployment/my-deploy --revision=2
```

**롤백**

```bash
# 바로 이전 버전으로
kubectl rollout undo deployment/my-deploy

# 특정 버전으로
kubectl rollout undo deployment/my-deploy --to-revision=2

# 확인
kubectl rollout status deployment/my-deploy
```

**일시정지/재개**

```bash
# 업데이트 일시정지
kubectl rollout pause deployment/my-deploy

# 재개
kubectl rollout resume deployment/my-deploy
```

### Rolling Update 설정

```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  replicas: 4
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1  # 업데이트 중 최대 몇개까지 내려가도 되나
      maxSurge: 1        # 업데이트 중 최대 몇개까지 더 띄워도 되나
```

```
replicas: 4 기준
maxUnavailable: 1  → 최소 3개는 항상 Running 유지
maxSurge: 1        → 최대 5개까지 동시에 존재 가능
```

---

### 배포 전략 2가지

```yaml
# 1. RollingUpdate (기본값) - 무중단
strategy:
  type: RollingUpdate

# 2. Recreate - 전부 죽이고 새로 띄움 (다운타임 있음)
strategy:
  type: Recreate
```

### CKAD 문제 패턴

**패턴 1 - 이미지 업데이트**

```
Task:
my-deploy의 nginx 컨테이너 이미지를
nginx:1.19로 업데이트하고
롤아웃 상태를 확인하라
```

```bash
kubectl set image deployment/my-deploy nginx=nginx:1.19
kubectl rollout status deployment/my-deploy
```

**패턴 2 - 롤백**

```
Task:
업데이트 후 Pod가 CrashLoopBackOff 상태다
이전 버전으로 롤백하라
```

```bash
kubectl rollout history deployment/my-deploy  # 히스토리 확인
kubectl rollout undo deployment/my-deploy      # 롤백
kubectl get pods                               # 확인
```

**패턴 3 - 특정 버전으로 롤백**

```
Task:
revision 2 버전으로 롤백하라
```

```bash
kubectl rollout undo deployment/my-deploy --to-revision=2
```

### 트러블슈팅 흐름

```bash
# 업데이트 후 문제 생기면
kubectl rollout status deployment/my-deploy
# "Waiting for rollout to finish" 멈춰있으면

kubectl get pods
# CrashLoopBackOff 확인

kubectl describe pod <pod-name>
# 원인 확인

kubectl rollout undo deployment/my-deploy
# 롤백
```
