## Labels, Selectors, Annotations

### Labels

리소스에 붙이는 **key-value 태그**. 검색/필터링 용도.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  labels:
    app: web        # 어떤 앱인지
    env: production # 어떤 환경인지
    tier: frontend  # 어떤 계층인지
```

```bash
# 라벨로 필터링
kubectl get pods -l app=web
kubectl get pods -l env=production,tier=frontend  # 여러개 조건
```

---

### Selectors

Labels를 **찾는 쿼리**. 리소스끼리 연결할 때 씀.

```yaml
# Service가 Pod를 찾을 때
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: web        # app=web 라벨 달린 Pod한테만 트래픽 보냄
```

```yaml
# Deployment가 자기 Pod 관리할 때
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  selector:
    matchLabels:
      app: web      # 이 라벨 달린 Pod를 내 Pod로 인식
  template:
    metadata:
      labels:
        app: web    # 여기랑 위 selector가 반드시 일치해야 함
```

---

### 셋의 관계 핵심

```
Labels    = 가격표 붙이기
Selectors = 그 가격표로 찾기

Pod ──[app=web 라벨]──→ Service Selector[app=web] 매칭
Pod ──[app=web 라벨]──→ Deployment Selector[app=web] 매칭
```

---

### Annotations

**메타데이터 저장용**. 검색/필터링 불가. 사람이나 툴이 읽는 정보.

```yaml
metadata:
  annotations:
    description: "주문 처리 서비스"
    contact: "kim@company.com"
    version: "1.2.3"
    prometheus.io/scrape: "true"   # 툴이 읽는 용도
```

---

### Labels vs Annotations 차이

||Labels|Annotations|
|---|---|---|
|**용도**|검색/필터링/연결|정보 저장|
|**Selector로 사용**|✅|❌|
|**값 제한**|짧고 단순해야 함|길어도 됨|
|**예시**|app=web, env=prod|담당자, 버전, 빌드정보|

### CKAD 문제 패턴

**패턴 1 - 라벨 추가**

```bash
# 명령어로 빠르게
kubectl label pod my-pod env=production

# 확인
kubectl get pods --show-labels
```

**패턴 2 - Service-Pod 연결 안될때**

```bash
# 이게 안 맞으면 트래픽 안 감
kubectl describe service my-service
# Selector: app=web 확인

kubectl get pods --show-labels
# Pod에 app=web 라벨 있는지 확인
```

**패턴 3 - 라벨로 필터링**

```bash
kubectl get pods -l env=production
kubectl get all -l app=web   # 모든 리소스 필터링
```

### 한 줄 요약

```
Labels      = 리소스에 태그 붙이기
Selectors   = 그 태그로 리소스 찾아서 연결
Annotations = 태그 말고 메모 적어두기
```





**Selector 쓰는 리소스들**

```
자주 쓰는 것 (CKAD 핵심)
├── Service       Pod 찾아서 트래픽 보내기
├── Deployment    자기 Pod 관리하기
├── ReplicaSet    자기 Pod 관리하기
└── Job           자기 Pod 관리하기

가끔 나오는 것
├── NetworkPolicy  특정 Pod에 네트워크 정책 적용
└── PodAffinity    특정 Pod 근처 노드에 스케줄링
```

---

**근데 CKAD 시험에서 실질적으로 중요한 건**

```
Service    ← Pod랑 연결 안될때 트러블슈팅 단골
Deployment ← selector, matchLabels 불일치 에러 단골
```

이 두 개가 시험에서 90% 이상 나옴.

---

**단골 실수 패턴**

```yaml
spec:
  selector:
    matchLabels:
      app: web       # ← 이거랑
  template:
    metadata:
      labels:
        app: webapp  # ← 이게 다르면 에러남
```

`selector`랑 `template.labels`가 **반드시 일치**해야 한다는 것만 기억해도 트러블슈팅 문제 절반은 풀림.
