## Job

한 번 실행하고 완료되는 작업.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-job
spec:
  completions: 3        # 총 3번 성공해야 완료
  parallelism: 2        # 동시에 2개 Pod 실행
  backoffLimit: 4       # 실패 시 재시도 횟수
  template:
    spec:
      restartPolicy: Never   # Job은 Never 또는 OnFailure만 가능
      containers:
      - name: my-container
        image: busybox
        command: ["echo", "hello"]
```

자주 나오는 포인트는 `completions`, `parallelism`, `backoffLimit`, `restartPolicy` 설정입니다.

## CronJob

Job을 주기적으로 실행. cron 표현식 사용.

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: my-cronjob
spec:
  schedule: "*/5 * * * *"        # 5분마다
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
          - name: my-container
            image: busybox
            command: ["echo", "hello"]
  successfulJobsHistoryLimit: 3   # 성공 기록 보관 수
  failedJobsHistoryLimit: 1       # 실패 기록 보관 수
  concurrencyPolicy: Forbid       # 동시 실행 정책
```

`concurrencyPolicy` 옵션은 세 가지입니다.

|값|설명|
|---|---|
|`Allow`|동시 실행 허용 (기본값)|
|`Forbid`|이전 Job 실행 중이면 스킵|
|`Replace`|이전 Job 취소하고 새로 실행|

## 시험 출제 빈도

```
Job       ★★★★    자주 나옴, 옵션 설정 문제
CronJob   ★★★★    schedule 표현식 + jobTemplate 구조
```

## 자주 쓰는 명령어

```bash
# Job 빠르게 생성
kubectl create job my-job --image=busybox -- echo hello

# CronJob 빠르게 생성
kubectl create cronjob my-cj --image=busybox \
  --schedule="*/5 * * * *" -- echo hello

# Job 상태 확인
kubectl get jobs
kubectl get pods --selector=job-name=my-job

# CronJob에서 Job 수동 실행
kubectl create job test --from=cronjob/my-cronjob
```

시험에서 yaml 처음부터 쓰는 것보다 `kubectl create job/cronjob` 으로 뼈대 뽑고 수정하는 게 훨씬 빠릅니다.
