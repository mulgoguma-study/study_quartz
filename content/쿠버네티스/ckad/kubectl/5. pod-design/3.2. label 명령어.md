kubectl --label과 -l 차이는 머야?

좋은 질문이에요. 둘 다 **label**을 다루지만 **역할이 완전히 다릅니다**. 자주 헷갈리는 포인트예요.

## 한 줄 요약

| 플래그                      | 역할                        |
| ------------------------ | ------------------------- |
| `--labels` (또는 `-l`은 아님) | 리소스 **생성할 때 붙이는** 라벨      |
| `-l` / `--selector`      | 리소스를 **조회/필터링할 때 쓰는** 셀렉터 |
|                          |                           |

이게 핵심인데, `-l`은 `--labels`의 축약형이 **아니에요**. `-l`은 `--selector`의 축약형입니다.

## `--labels` — 생성 시 라벨 부착

리소스를 **만들 때** 라벨을 붙입니다.

```bash
kubectl run redis --image=redis:7 --labels='app=cache,tier=backend'
```

결과 Pod:

```yaml
metadata:
  name: redis
  labels:
    app: cache
    tier: backend
```

`kubectl run`, `kubectl create` 같은 **생성 명령어**에서 사용.

## `-l` / `--selector` — 조회 시 필터

이미 존재하는 리소스 중에서 **라벨 조건에 맞는 것만** 골라냅니다.

```bash
# app=cache 라벨이 붙은 Pod만 조회
kubectl get pods -l app=cache

# 여러 조건 (AND)
kubectl get pods -l 'app=cache,tier=backend'

# 부정 조건
kubectl get pods -l 'app!=cache'

# 존재 여부
kubectl get pods -l 'app'          # app 라벨 있는 것
kubectl get pods -l '!app'         # app 라벨 없는 것

# in 조건
kubectl get pods -l 'tier in (backend,frontend)'
```

`get`, `delete`, `describe`, `logs` 같은 **조회/조작 명령어**에서 사용.

## 실전 예시 — 같이 써보기

```bash
# 1. 라벨 붙여서 Pod 생성 (--labels 사용)
kubectl run redis1 --image=redis:7 --labels='app=cache,env=dev'
kubectl run redis2 --image=redis:7 --labels='app=cache,env=prod'
kubectl run nginx1 --image=nginx   --labels='app=web,env=dev'

# 2. 특정 라벨 가진 것만 조회 (-l 사용)
kubectl get pods -l app=cache
# → redis1, redis2

kubectl get pods -l env=dev
# → redis1, nginx1

kubectl get pods -l 'app=cache,env=prod'
# → redis2만

# 3. 라벨로 대량 삭제
kubectl delete pods -l env=dev
# → redis1, nginx1 삭제
```

## `kubectl label` — 또 다른 친구

이미 존재하는 리소스에 라벨을 **추가/변경**할 때:

```bash
# 라벨 추가
kubectl label pod redis tier=backend

# 라벨 덮어쓰기 (기존 키가 있을 때)
kubectl label pod redis app=memory-cache --overwrite

# 라벨 삭제 (키 뒤에 -)
kubectl label pod redis tier-
```

## 표로 정리

|플래그|어디서 씀|예시|
|---|---|---|
|`--labels`|생성 (`run`, `create`)|`--labels='app=cache'`|
|`-l` / `--selector`|조회/조작 (`get`, `delete` 등)|`-l app=cache`|
|`kubectl label`|기존 리소스 라벨 수정|`kubectl label pod x foo=bar`|

## Go 개발자 관점의 비유

SQL로 치면 이런 느낌이에요:

```sql
-- --labels: INSERT할 때 값 지정
INSERT INTO pods (name, label) VALUES ('redis', 'app=cache');

-- -l: SELECT할 때 WHERE 절
SELECT * FROM pods WHERE label = 'app=cache';

-- kubectl label: UPDATE
UPDATE pods SET label = 'app=cache' WHERE name = 'redis';
```

## CKAD 시험에서 자주 나오는 패턴

```bash
# "app=web 라벨 가진 Pod 다 지워라"
kubectl delete pods -l app=web

# "특정 라벨 가진 Pod 로그 봐라"
kubectl logs -l app=cache --tail=50

# "특정 Deployment의 Pod들만 골라내라"
kubectl get pods -l app=myapp -o wide
```

`-l`은 CKAD 시험에서 **필터링 속도**를 엄청 올려주니 꼭 익숙해지세요. 한 번 `-l`로 고르고 나면 그 대상에 describe, logs, delete를 전부 적용할 수 있어요.
