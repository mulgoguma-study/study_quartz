Core Concepts는 다른 영역의 기반이라 단독 문제보다 **다른 문제의 일부로** 자주 등장합니다.

#### 패턴 1: 특정 namespace에 리소스 생성

"dev namespace에 nginx Pod을 만들어라."

bash

```bash
k create ns dev    # 이미 있으면 스킵
k run nginx --image=nginx -n dev
```

또는 작업 전에 default namespace 변경:

bash

```bash
k config set-context --current --namespace=dev
k run nginx --image=nginx
```

#### 패턴 2: Pod 생성 + 라벨/포트/명령어

"app=web 라벨을 가진 nginx Pod을 만들고, 80 포트를 노출하라."

bash

```bash
k run nginx --image=nginx --labels="app=web" --port=80
```

명령어 지정:

bash

```bash
k run my-pod --image=busybox $do -- sleep 3600 > pod.yaml
```

#### 패턴 3: 특정 라벨의 Pod만 조회/삭제

"env=prod 라벨을 가진 Pod의 이름을 파일에 저장하라."

bash

```bash
k get pods -l env=prod -o name > /opt/prod-pods.txt
# 또는
k get pods -l env=prod -o jsonpath='{.items[*].metadata.name}' > /opt/prod-pods.txt
```

#### 패턴 4: 리소스의 특정 필드 추출

"web Pod의 IP를 파일에 저장하라."

bash

```bash
k get pod web -o jsonpath='{.status.podIP}' > /opt/ip.txt
```

"모든 Pod의 이미지 목록을 파일에 저장하라."

bash

```bash
k get pods -o jsonpath='{.items[*].spec.containers[*].image}' > /opt/images.txt
```

#### 패턴 5: YAML로 출력 후 수정

"기본 Pod을 만들고 securityContext를 추가하라."

bash

```bash
k run my-pod --image=nginx $do > pod.yaml
vi pod.yaml          # securityContext 추가
k apply -f pod.yaml
```

#### 패턴 6: 여러 리소스 한 번에 조회

"dev namespace의 모든 리소스를 보여라."

bash

```bash
k get all -n dev
```

`get all`은 Pod, Service, Deployment, ReplicaSet, StatefulSet, DaemonSet, Job 등 주요 리소스를 다 보여줍니다. ConfigMap, Secret, Ingress 등은 별도.

### 함정 포인트

#### 함정 1 — Namespace 누락

bash

```bash
k get pod                          # default namespace만
k get pod -n dev                   # dev namespace
k get pod -A                       # 전체
```

문제에서 namespace를 명시하면 반드시 `-n` 사용. 작업 namespace를 미리 바꿔두는 게 안전:

bash

```bash
k config set-context --current --namespace=dev
```

#### 함정 2 — `kubectl run`의 동작 변경

이전 버전에서는 Deployment를 만들기도 했지만, **현재(1.18+)는 Pod만 생성**합니다.

bash

```bash
k run nginx --image=nginx        # Pod 생성 (Deployment 아님)
```

Deployment를 원하면 명시적으로:

bash

```bash
k create deploy nginx --image=nginx
```

#### 함정 3 — `--restart=Never`로 Pod 강제

`k run`은 가끔 옵션에 따라 Job을 만들기도 합니다. 확실히 Pod만 만들려면:

bash

```bash
k run my-pod --image=nginx --restart=Never
```

`--rm -it --restart=Never`는 임시 디버깅 Pod 만들 때 표준 조합.

#### 함정 4 — `apply`와 `create` 혼용

bash

```bash
k create -f pod.yaml         # ❌ 이미 있으면 에러
k apply -f pod.yaml          # ✅ 있으면 업데이트, 없으면 생성
```

YAML 파일로 작업할 때는 `apply`가 일반적으로 안전.

#### 함정 5 — `delete --force`는 마지막 수단

bash

```bash
k delete pod my-pod --grace-period=0 --force
```

이건 graceful shutdown을 건너뜁니다. 데이터 손실 가능. 시간 압박이 있을 때만.

#### 함정 6 — `$do`로 만든 YAML의 불필요 필드

bash

```bash
k run my-pod --image=nginx $do > pod.yaml
```

생성된 YAML에 `creationTimestamp: null`, `status: {}` 같은 불필요 필드가 있을 수 있습니다. 그대로 apply해도 동작은 하지만 깔끔히 지워도 됨. 시험에선 시간 낭비이므로 무시.

#### 함정 7 — 단축명 헷갈림

bash

```bash
k get svc            # services (O)
k get sv             # ❌ 정의되지 않음
k get sa             # serviceaccounts (O)
k get serviceaccount # 풀네임 (O)
```

확실하지 않으면 풀네임 사용. `k api-resources`로 정확한 단축명 확인.

#### 함정 8 — 라벨 selector의 따옴표

bash

```bash
k get pods -l app=web                  # OK
k get pods -l 'env in (prod, dev)'     # ✅ 따옴표 필수
k get pods -l '!env'                   # ✅ 따옴표 필수
```

shell이 특수문자를 해석하지 않게 따옴표로 감싸기.

#### 함정 9 — JSONPath의 따옴표

bash

```bash
# 큰따옴표 안에서 작은따옴표 사용
k get pod -o jsonpath='{.items[*].metadata.name}'

# 줄바꿈 포함
k get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'
```

JSONPath 표현식 자체를 작은따옴표로 감싸는 게 안전.

#### 함정 10 — namespace 삭제 시 안의 리소스도 삭제

bash

```bash
k delete ns dev   # 안의 모든 Pod, Service, Deployment 등 함께 삭제
```

실수로 namespace 삭제하면 복구 안 됨. 신중히.

### 디버깅 명령 (기본 흐름)

bash

```bash
# 표준 흐름 (외워둘 것)
k get <resource>              # 1. 상태 확인
k describe <resource> <name>  # 2. 상세 + 이벤트
k logs <pod>                  # 3. 로그
k logs <pod> --previous       # 4. 크래시 전 로그
k exec -it <pod> -- sh        # 5. 직접 들어가기
k get events --sort-by=.metadata.creationTimestamp   # 6. 이벤트
```

### 빠르게 작성하는 팁

- **시험 시작 직후 alias + namespace 세팅**. 5분 투자로 2시간 절약.
- **`k <command> --help`** 적극 활용. Kubernetes 명령은 옵션이 많아서 도움말이 가장 빠름.
- **`$do`는 황금**:

bash

```bash
  k run my-pod --image=nginx $do > pod.yaml
  k create deploy web --image=nginx $do > deploy.yaml
  k create cm app --from-literal=K=V $do > cm.yaml
  k create svc clusterip my-svc --tcp=80:8080 $do > svc.yaml
```

명령어로 안 되는 필드만 YAML 편집.

- **`k api-resources`로 단축명 확인**. 헷갈리면 즉시 조회.
- **`k explain --recursive | less`로 필드 검색**. `/<keyword>`로 vi처럼 검색.
- **`-o name`은 다른 명령과 조합하기 좋음**:

bash

```bash
  k get pods -l app=web -o name | xargs k delete
```

- **namespace 항상 의식**: 문제 풀기 전 `k config view --minify | grep namespace`로 확인.
- **모르겠으면 `kubectl explain`**. 모든 답이 여기에 있음.
- **`k get all`로 한 번에 보기**: namespace 전체 상태 빠르게 파악.
- **YAML 파일 관리**: 시험 도중 만든 yaml은 의미있는 이름으로(`/tmp/pod-1.yaml`, `/tmp/deploy.yaml`), 나중에 재사용 가능.

### 자주 헷갈리는 차이 정리

|명령|동작|사용 시점|
|---|---|---|
|`k run`|Pod 1개 생성|빠른 Pod 생성, 디버깅용|
|`k create deploy`|Deployment 생성|운영용|
|`k create`|리소스 새로 생성|처음 만들 때|
|`k apply`|생성 또는 업데이트|YAML 파일 관리|
|`k expose`|Service 생성|Deployment/Pod 노출|
|`k edit`|인터랙티브 편집|즉시 수정|
|`k set`|특정 필드 변경|이미지/리소스/환경변수만|
|`k scale`|replicas 변경|개수만|
|`k label` / `k annotate`|라벨/어노테이션|메타데이터|

|단축명|풀네임|
|---|---|
|`po`|pods|
|`deploy`|deployments|
|`rs`|replicasets|
|`svc`|services|
|`ns`|namespaces|
|`cm`|configmaps|
|`ing`|ingresses|
|`ep`|endpoints|
|`sa`|serviceaccounts|
|`pv`|persistentvolumes|
|`pvc`|persistentvolumeclaims|
|`no`|nodes|
|`cj`|cronjobs|
|`netpol`|networkpolicies|
|`hpa`|horizontalpodautoscalers|

|출력 포맷|용도|
|---|---|
|`-o wide`|IP, Node 포함|
|`-o yaml`|전체 YAML|
|`-o json`|JSON|
|`-o name`|이름만 (xargs 조합용)|
|`-o jsonpath='{...}'`|특정 필드 추출|
|`-o custom-columns=...`|커스텀 컬럼|

|리소스 범위|예시|
|---|---|
|Namespaced|Pod, Deploy, Svc, CM, Secret, PVC, SA, Role, RB, Job, CJ, Ing, NetPol|
|Cluster|NS, Node, PV, ClusterRole, ClusterRoleBinding, StorageClass|

|자주 쓰는 컨텍스트 명령|효과|
|---|---|
|`k config current-context`|현재 context|
|`k config view --minify`|현재 context 상세|
|`k config get-contexts`|context 목록|
|`k config use-context <name>`|context 전환|
|`k config set-context --current --namespace=<ns>`|기본 namespace 변경|

---

Core Concepts는 **CKAD 모든 문제의 기반**이 되는 영역입니다. 깊은 이론보다 **kubectl 명령어를 손에 익히는 것**이 가장 중요합니다. 특히 imperative 명령 + `$do` + YAML 수정 흐름, namespace 컨텍스트 관리, JSONPath 추출, 자주 쓰는 단축명 이 네 가지는 시험 내내 반복적으로 사용되니 머리에 완전히 박힐 때까지 연습하세요. 시험 시작 직후 5분 동안 alias, 자동완성, vi 설정, namespace 확인을 마치는 습관이 점수에 가장 큰 영향을 줍니다.
