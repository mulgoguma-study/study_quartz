### 1. Kubernetes 아키텍처 (기본 이해)

CKAD에서 깊이 다루지는 않지만 용어는 알아야 합니다.

#### Control Plane (master 노드)

- **kube-apiserver**: 모든 통신의 진입점. kubectl도 여기에 요청
- **etcd**: 클러스터 상태를 저장하는 key-value DB
- **kube-scheduler**: Pod을 어느 노드에 배치할지 결정
- **kube-controller-manager**: 각종 컨트롤러 실행 (Deployment, ReplicaSet 등)

#### Worker 노드

- **kubelet**: 노드에서 Pod 생명주기 관리
- **kube-proxy**: 네트워크 라우팅 (Service 구현)
- **Container Runtime**: containerd, CRI-O 등 (Docker는 1.24+ 제거)

bash

```bash
# 노드 확인
k get nodes
k get nodes -o wide
k describe node worker-1
```

### 2. Kubernetes API Primitives

#### 모든 리소스의 공통 구조

yaml

```yaml
apiVersion: v1                # 리소스의 API 그룹/버전
kind: Pod                     # 리소스 종류
metadata:                     # 메타데이터
  name: my-pod
  namespace: default
  labels:
    app: web
  annotations:
    description: "web server"
spec:                         # 원하는 상태 (사용자 정의)
  containers:
  - name: app
    image: nginx
status:                       # 현재 상태 (시스템이 자동 채움)
  phase: Running
```

핵심 4개 필드: `apiVersion`, `kind`, `metadata`, `spec`. 이 구조를 머리에 박아두세요.

#### 주요 API 그룹/버전

|리소스|apiVersion|
|---|---|
|Pod, Service, ConfigMap, Secret, Namespace, PV, PVC, ServiceAccount|`v1`|
|Deployment, ReplicaSet, StatefulSet, DaemonSet|`apps/v1`|
|Job, CronJob|`batch/v1`|
|Ingress, NetworkPolicy|`networking.k8s.io/v1`|
|Role, RoleBinding, ClusterRole, ClusterRoleBinding|`rbac.authorization.k8s.io/v1`|
|HorizontalPodAutoscaler|`autoscaling/v2`|

`apiVersion`을 헷갈릴 때:

bash

```bash
k api-resources
k api-resources | grep deploy
k explain deploy           # 첫 줄에 apiVersion 표시
```

### 3. kubectl 기본 사용법

#### 명령 구조

bash

```bash
kubectl <action> <resource> [name] [flags]
```

**주요 action**:

- `get`: 리소스 조회
- `describe`: 상세 정보
- `create`: 새로 생성 (이미 있으면 에러)
- `apply`: 생성 또는 업데이트 (선언적)
- `delete`: 삭제
- `edit`: 직접 편집
- `exec`: 컨테이너 내부 명령
- `logs`: 로그 확인
- `expose`: Service 생성
- `run`: Pod 생성
- `scale`: replica 변경
- `rollout`: 배포 관리
- `set`: 특정 필드 변경
- `label` / `annotate`: 라벨/어노테이션 관리

#### Imperative vs Declarative

**Imperative (명령형)**: 명령어로 즉시 실행

bash

```bash
k run nginx --image=nginx
k create deploy web --image=nginx
k expose deploy web --port=80
```

**Declarative (선언형)**: YAML로 원하는 상태 선언

bash

```bash
k apply -f deploy.yaml
```

**CKAD 전략**: 거의 모든 문제는 **imperative + `$do` + YAML 수정** 조합이 가장 빠릅니다.

bash

```bash
k create deploy web --image=nginx $do > deploy.yaml
# YAML 수정
k apply -f deploy.yaml
```

#### `create` vs `apply`

|항목|create|apply|
|---|---|---|
|기존 리소스 있음|에러|업데이트|
|기존 리소스 없음|생성|생성|
|추적|안 함|`last-applied-configuration` 어노테이션 추가|
|추천|처음 생성|YAML 파일 관리 시|
