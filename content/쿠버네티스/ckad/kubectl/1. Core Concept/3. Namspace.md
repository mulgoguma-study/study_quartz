리소스를 논리적으로 격리하는 단위. 같은 namespace 안에서는 이름이 unique해야 합니다.

#### 기본 namespace

- `default`: 별도 지정 안 했을 때
- `kube-system`: 시스템 컴포넌트
- `kube-public`: 모두가 읽을 수 있는 공개 정보
- `kube-node-lease`: 노드 heartbeat

#### 생성과 사용

bash

```bash
# 생성
k create namespace dev
k create ns dev

# 모든 namespace 조회
k get ns

# 특정 namespace의 리소스
k get pods -n dev
k get pods --namespace=dev

# 모든 namespace의 리소스
k get pods -A
k get pods --all-namespaces

# Pod을 특정 namespace에 생성
k run my-pod --image=nginx -n dev
```

#### Namespace 기본값 변경 (context)

bash

```bash
# 현재 context 확인
k config current-context
k config view --minify

# 기본 namespace 변경
k config set-context --current --namespace=dev

# 확인
k config view --minify | grep namespace
```

이후 `-n` 없이도 dev에 작업됩니다. CKAD 시험에서 시간 절약에 매우 유용.

#### Namespace 범위 vs Cluster 범위

**Namespaced 리소스** (namespace에 종속): Pod, Deployment, Service, ConfigMap, Secret, PVC, Role, RoleBinding, ServiceAccount, Job, CronJob, Ingress, NetworkPolicy

**Cluster 리소스** (namespace 없음): Namespace 자체, Node, PV, ClusterRole, ClusterRoleBinding, StorageClass

확인:

bash

```bash
k api-resources --namespaced=true
k api-resources --namespaced=false
```
