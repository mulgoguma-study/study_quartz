한 마디로 요약하면:

> **"여러 서버에서 컨테이너를 자동으로 관리해주는 시스템"**

---

## 쿠버네티스가 없으면?

서버 3대에 Go 서버를 배포한다고 가정하면:

```
❌ 직접 ssh로 각 서버 접속
❌ 각각 docker run으로 실행
❌ 하나가 죽으면 직접 가서 재시작
❌ 트래픽 늘면 직접 서버 더 띄우기
❌ 새 버전 배포하면 하나씩 접속해서 업데이트
```

---

## 쿠버네티스가 있으면?

```
✅ "Go 서버 3개 항상 실행해줘" → 죽으면 자동 재시작
✅ "트래픽 많아지면 알아서 늘려줘" → 오토스케일링
✅ "새 버전 배포해줘" → 무중단 롤링 업데이트
✅ "서버1이 터져도 괜찮게 해줘" → 자동 다른 서버로 이동
```

---

## 핵심 기능 5가지

### 1. 자동 복구 (Self-healing)

```
Pod이 죽으면 → 자동으로 다시 띄움
서버가 죽으면 → 다른 서버에 옮겨서 띄움
```

### 2. 스케일링

```bash
# 이 한 줄로 Go 서버를 10개로 늘림
kubectl scale deployment my-go-server --replicas=10
```

### 3. 무중단 배포

```
v1.0 실행 중 → v1.1 서서히 교체 → 사용자는 중단 없음
문제 생기면 → kubectl rollout undo 한 줄로 롤백
```

### 4. 로드밸런싱

```
사용자 요청 → 쿠버네티스가 자동으로 여러 Pod에 분산
```

### 5. 설정/비밀값 관리

```bash
# DB 비밀번호 같은걸 코드에 안 넣고 따로 관리
kubectl create secret generic db-secret --from-literal=password=1234
```

## Go 개발자 입장에서 실감나는 예시

```
[내가 만든 Go API 서버]
    ↓ Docker 이미지로 빌드
    ↓ k3s에 배포
    
이제 k3s가 알아서:
- 3대 PC에 분산해서 실행
- 하나 죽으면 다시 살림
- /healthz 찍어서 이상하면 교체
- 새 버전 올리면 순차적으로 교체
```

## 한 줄 정리

|없을 때|있을 때|
|---|---|
|내가 서버 관리|쿠버가 서버 관리|
|수동 복구|자동 복구|
|수동 스케일링|자동 스케일링|
|배포 = 긴장|배포 = 명령어 한 줄|

결국 **"운영을 자동화"** 하는 도구입니다. 서버가 1~2대면 오버스펙이지만, 여러 서비스가 여러 서버에서 돌아야 할 때 진가가 나와요.
